# OctoAcme Project Management Docs

## Overview
OctoAcme follows a structured, iterative project management approach focused on customer value, clear ownership, and data-informed decisions. The organization uses a lightweight lifecycle that moves from validating a business need through planning, execution, release, and retrospection. This helps teams align on the right problem, work in visible increments, and learn quickly from delivery outcomes.

At a high level, OctoAcme’s process emphasizes clear role ownership, regular communication, measurable outcomes, and disciplined quality gates. Teams define success metrics early, break work into shippable units with explicit acceptance criteria, manage dependencies and risks throughout delivery, and rely on retrospectives to convert lessons learned into improvements. The result is a repeatable project rhythm that supports both operational clarity and continuous improvement.

## Core Principles
- Customer-first delivery
- Iterative, incremental development
- Clear ownership and accountability
- Data-informed decisions
- Psychological safety and continuous learning

## Project Lifecycle
OctoAcme projects flow through six key phases:

### 1. **Initiation** — Validate & Authorize
- Define the problem and business case
- Identify stakeholders and secure alignment
- Create a lightweight Project One-pager
- Decision gate: Approve for planning?

### 2. **Planning** — Create an Actionable Plan
- Break work into shippable increments
- Define acceptance criteria and Definition of Done
- Identify dependencies and risks
- Create release plan and milestones

### 3. **Execution & Tracking** — Build & Measure Progress
- Daily standups and sprint cycles
- Pull Request workflow with automated quality checks
- Track velocity, burndown, and success metrics
- Escalate blockers through defined channels

### 4. **Release & Deployment** — Ship to Production
- Execute pre-release checklist
- Deploy with confidence (automated pipeline preferred)
- Run post-deploy verification
- Communicate release to stakeholders

### 5. **Retrospective & Continuous Improvement** — Learn & Improve
- Capture what went well and areas for improvement
- Create actionable improvement items
- Track action items to completion
- Celebrate wins and iterate

### 6. **Risk & Communication** — Identify & Manage Risks
- Maintain a living risk register
- Communicate status and risks to stakeholders
- Escalate issues through defined paths
- Respond to incidents with blameless retrospectives

## Key Roles
- **Project Manager (PM)** — Coordinates delivery, manages timeline, risk, and communications
- **Product Manager (PdM)** — Defines outcomes, prioritizes backlog, measures success
- **Developers** — Implement features, collaborate on design and quality
- **QA/Testing** — Validate acceptance criteria and quality standards

## Quick Reference

### Checklists
Each process doc includes specific checklists. Key gates:
- **After Initiation:** Success metrics clear? Stakeholders aligned? Go/no-go to planning?
- **After Planning:** Backlog prioritized? Definition of Done documented? Risks identified?
- **After Execution:** All acceptance criteria met? CI passing? Smoke tests ready?
- **After Release:** Deployment verified? Stakeholders notified? Post-incident review scheduled?

### Communication Cadence
- Daily standups (15 min)
- Weekly PM + PdM sync
- Twice-weekly team standups (or as agreed)
- Monthly stakeholder updates
- Ad-hoc escalations as needed
